# 0002. Assistive-only модель безопасности для удаления веток

- **Status:** accepted
- **Date:** 2026-08-30

## Context

Одна из ключевых функций проекта — помощь в очистке локальных и удалённых веток. Ошибка в такой операции может привести к потере работы, удалению production/release-ветки или чужого незамерженного кода.

Альтернативы: выполнять удаление прямо из TUI, автоматически удалять ветки после Jira/release-проверок, генерировать команды без дополнительной защиты.

## Decision

Проект работает в assistive-only режиме:

- TUI только помогает найти и отметить кандидатов на удаление;
- автоматические механизмы (`branch.autocheck`, release-driven autocheck) только предлагают выбор;
- окончательное действие — генерация `.sh`/`.bat` скрипта;
- пользователь вручную просматривает и запускает скрипт вне приложения;
- системные/защищённые ветки блокируются через `branch.keep`, текущую ветку и remote-default проверки;
- shell/BAT генерация использует sanity-check и экранирование branch names.

## Consequences

Плюсы:

- нет silent auto-run и автоматического удаления;
- риск деструктивного действия перенесён в явный ручной шаг;
- пользователь может отменить любую автопометку перед генерацией скрипта;
- модель хорошо объясняется в README и SECURITY-документации.

Минусы:

- процесс удаления требует дополнительного ручного шага;
- приложение не может закрыть весь cleanup-cycle само;
- нужно поддерживать безопасную генерацию скриптов для разных shell dialects.

Это сознательный trade-off в пользу безопасности и контроля пользователя.
