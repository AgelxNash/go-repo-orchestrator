# 0001. Использовать BubbleTea MVU для TUI

- **Status:** accepted
- **Date:** 2026-08-30

## Context

Проекту нужен интерактивный терминальный интерфейс для управления множеством репозиториев, просмотра веток, статусов Jira, dirty-state и генерации безопасных скриптов удаления. Интерфейс должен поддерживать асинхронную загрузку данных, горячие клавиши, модальные подтверждения и предсказуемую отрисовку.

Альтернативы: обычный CLI с подкомандами, самописный терминальный loop, другие TUI-библиотеки. Обычный CLI хуже подходит для постоянной навигации и сравнения состояния нескольких репозиториев; самописный loop повышает риск ошибок состояния и отмены операций.

## Decision

Использовать BubbleTea и MVU-подход: `Model` хранит состояние интерфейса, `Update` принимает сообщения и возвращает новую модель с командой, `View` строит строковое представление.

Асинхронные операции запускаются через `tea.Cmd`, а долгие Git/Jira/Playwright действия получают `context.Context` и управляются action-key/cancel механизмом.

## Consequences

Плюсы:

- состояние TUI централизовано и тестируемо через сообщения;
- асинхронность согласована с BubbleTea runtime;
- можно покрывать UX-сценарии unit-тестами модели без настоящего терминала.

Минусы:

- `Model` легко становится крупным объектом с большим количеством полей;
- обработчик `Update` нужно регулярно декомпозировать, чтобы не получить god-function;
- бизнес-операции нужно держать за портами/интерфейсами, иначе presentation layer слишком плотно связывается с usecase-реализациями.

Текущее развитие: `Model.Update` разделён на message handlers, TUI переведён на `cleanerPort`.
